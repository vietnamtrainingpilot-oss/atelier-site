Install

One line, then restart.

Requires Node 18+ and git. Nothing is registered until your agent restarts — skills load at startup, so a running session will not see them.

node install.mjs

Run it from a clone:

git clone https://github.com/vietnamtrainingpilot-oss/atelier
cd atelier
node install.mjs

Or skip the clone entirely:

curl -fsSL https://raw.githubusercontent.com/vietnamtrainingpilot-oss/atelier/main/install.sh | bash

What it actually does

Three steps, in this order, for every skill the routers declare.

1. Resolves each dependency

For every skill a router requires, the installer looks in three places and takes the first hit. An existing install wins, so re-running is safe and never clobbers a skill you already had.

already installed→bundled in the repo→public GitHub

2. Writes to your host's skill root

It detects the agent you are running under, then copies skills into that host's directory. Thirty-six skills ship inside the repository — the ones whose upstream was never public — so an offline install still gives you a working core. The remaining public skills are cloned from their own GitHub sources at install time.

3. Writes the parts that are not skills

The eight cs-* security subagents, and on opencode the plugin that nudges a router when its stack is incomplete. It also rewrites CLAUDE_PLUGIN_ROOT inside claude-security's markdown, which is unset outside Claude Code and breaks that skill if left alone.

A fetch that fails is reported, not hidden. The router still loads and tells you which skills it could not get.

Flags

FlagEffect
--checkReport what would change. Installs nothing, fetches nothing.
--listList every router with its dependency count.
--offlineInstall from bundled skills only. Zero network requests.
--prefer-networkRefresh public skills from upstream even when a bundled copy exists.
--forceOverwrite existing skills. Without it, an existing copy is left alone.
--agent <name>Target a host explicitly: opencode, claude, agents, cursor, codex, windsurf, gemini.
--root <path>Install somewhere else entirely.
--jsonMachine-readable summary on stdout.
--in-placeInstall the routers into the current checkout instead of a managed copy.

Name a router instead of a flag to install just that domain: node install.mjs web-design, or node install.mjs --check seo to see what it would do.

Troubleshooting

The skills are installed but the agent cannot see them.

Restart it. Skills are only registered at startup, so a session that was already running when you installed will keep its old list no matter what.

It picked the wrong host.

Pass it explicitly: node install.mjs --agent claude. Detection only looks at which config directories exist, so an agent you have installed but never run may not be on disk yet.

A public skill failed to fetch.

Usually a network or git problem, not an Atelier bug. Re-run without --offline, or point --root at the directory you wanted and try --prefer-network to bypass a stale bundled copy.

A router reports that a skill is missing.

That is deliberate — it will not pretend a skill is present. Run node install.mjs <router> --check to see exactly which ones it could not resolve.

You want zero network traffic.

node install.mjs --offline. The thirty-six bundled skills still install; the public ones are reported unavailable instead of being silently skipped.

claude-security mentions an unset variable.

Its markdown references ${CLAUDE_PLUGIN_ROOT}, which only exists inside Claude Code. The installer rewrites it to the real path on install; re-run with --force if you copied it in by hand.
