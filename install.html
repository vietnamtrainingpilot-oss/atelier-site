Install

Two lines, then you're routing.

Node 18 or later. Two lines, or one if your agent hasn't been run yet — auto-detection can only see agents whose config directories already exist.

One line, auto-detected across seven agents.

Both one-liners clone to ~/.atelier and forward every argument through to node install.mjs, so all flags below work unchanged.

Prefer to clone it yourself?

Useful if you want to read the installer before it runs.

git clone https://github.com/vietnamtrainingpilot-oss/atelier
cd atelier
node install.mjs

The clone is reusable — git pull then re-run the installer to update.

Auto-detection checks opencode, claude, cursor, codex, then agents. Windsurf and Gemini are reachable only with --agent.

Already use the skills CLI?

One command, no installer script.

npx skills add vietnamtrainingpilot-oss/atelier

The skills CLI copies router skills only. For the full install — bundled skills, the opencode plugin, security subagents, dependency resolution — use the installer above.

There is also a reason the installer avoids it internally: npx skills add re-spawns a bare npx, which fails with ENOENT on Windows whenever stdio is piped, and pulls an npm dependency in for what is only a clone and a copy.

Only need one domain?

Run these from inside the clone — cd ~/.atelier first.

node install.mjs web-design
node install.mjs video-production
node install.mjs security

Installing one router installs its skills only. Everything else can come later.

Flags

All verified against install.mjs.

FlagWhat it does
(none)Install everything, bundled skills first
<router>Install a single router, e.g. web-design
--agent <name>Skip auto-detection and target one host
--root <path>Install to a custom directory instead of the agent's skills root
--offlineBundled skills only, zero network requests
--prefer-networkRefresh public skills from upstream even when a bundled copy exists
--checkReport what would happen, change nothing
--forceOverwrite skills that are already installed
--listPrint the eight routers and exit
--jsonMachine-readable summary on stdout
--in-placeInstall into the clone instead of a skill root

--agent accepts exactly: opencode, claude, cursor, codex, windsurf, gemini, agents.

Restart your agent after installing. Skills register at startup, not mid-session.

When it goes wrong.

The five failures that actually come up.

Installed, but the agent cannot see the skills.

Restart it. Skills register at startup only, so a session that was already running keeps its old list no matter what you install.

It picked the wrong host.

Pass --agent <name> explicitly. Detection only looks for config directories that already exist on disk, so an agent you installed but never launched may not be visible to it yet.

A public skill failed to fetch.

Usually a network or git problem rather than an Atelier bug. Re-run without --offline, or use --prefer-network to bypass a stale bundled copy.

A router reports a skill is missing.

That is deliberate — it will not pretend a skill is present. Run node install.mjs <router> --check to see exactly which ones it could not resolve.

claude-security mentions an unset variable.

Its markdown references ${CLAUDE_PLUGIN_ROOT}, which only exists inside Claude Code. The installer rewrites it to the real absolute path on install; re-run with --force if you copied it in by hand.
