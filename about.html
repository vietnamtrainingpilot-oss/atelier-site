About

A workshop, not a toolbox.

An atelier is where you bring the commission and someone engages the right craftsperson for it. Atelier is that word taken literally: you bring the job, it dispatches the specialist.

Why it exists

Because skill selection had quietly become your job, and it is a bad one.

Install forty skills and every request turns into the same unfun question: which eleven of these forty do I need this time? Worse, a fifth of them are near-duplicates competing for the same job — four different taste skills that each impose a completely different visual language, none of which can tell you it is the wrong one for this page.

Atelier replaces you with eight entry points. Each one knows its whole domain, names a lead, adds at most two supports, and hands off to another router when the work crosses a boundary. You stop choosing between specialists. You state the job.

That is the entire claim, and it is a small one on purpose. It is not that the specialists got better — they are the same skills other people already wrote and published. It is that you no longer have to know they exist, or know which of them to trust for which job.

Getting there costs one line. It clones the repo to ~/.atelier, works out which agent you are running, and writes 105 skills into that agent's skills directory. Thirty-six of them ship inside the plugin; the rest are cloned from their own upstream at install time.

What it values

Useful over impressive

A router that installs, dispatches, verifies and hands off beats one that claims a larger surface. Coverage is not the goal; the job getting done is.

Explicit over magic

Every selection is printed: router, lead, supports, hand-off. When something is missing it says which skill and why. It never pretends to have something it does not.

Honest about limits

No installed skill covers infrastructure-as-code, database migrations, observability or API design. No dedicated debugging skill ships either. Those gaps are written down instead of papered over.

The eight domains

Named for the job, never for the tool — so the underlying skills can change without renaming anything.

web-design
Landing pages, portfolios, redesigns, design systems, UI, and scroll or cinematic motion.
video-production
HTML-to-video, React video, and social promo — selected by the input you bring, not the output you want.
seo
An ordered pipeline from project setup to the report you actually send a client.
backend
APIs, data, auth, architecture, refactors and the archaeology of an unfamiliar codebase.
payments
Stripe, loaded from the official source rather than from model memory, with the PCI-relevant rules enforced.
security
Scanning, verifying, patching and redacting — with the agent boundaries left intact.
vibe-code
The deliberate shortcut: vague idea in, running thing out, no ceremony in between.
ship-it
The process spine. Verification is a gate you cannot walk past on a good day.

Security, and what it cannot do

The one place where the honest answer is a limitation rather than a feature.

Known limitation

Anthropic's claude-security skill orchestrates eight subagents through Claude Code's Workflow(...) engine. That engine does not exist in opencode, so Atelier ships the dispatch order in place of the orchestrator: inventory → research → verify → generate → verify patch. There is no one-click /security scan, and pretending otherwise would be the more useful lie.

Six of the eight subagents are read-only with edit: deny, which is the important half — a scan that cannot write cannot damage the thing it is scanning. The full list and their roles are on the security router entry.

Judge it on one line.

One line, auto-detected across seven agents. Restart your agent, invoke one router, and see whether the selection it printed was the one you would have made.
