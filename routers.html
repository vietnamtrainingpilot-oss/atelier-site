The eight routers

One lead skill, at most two supports. Loading five design skills produces mush, not a better site — so the router commits to one, and says why.

web-design

Landing pages, portfolios, redesigns, design systems, UI, and scroll or cinematic motion. Routes by job type, not by vibe.

Dependencies
46 skills
Lead skill
ai-ui-ux-motion-engine — the default for a new landing page
Supports
ui-ux-pro-max when the work is client-facing and palettes matter · awwwards-animations when the motion is the deliverable
Hands off to
video-production — the visual system is decided once and both routers inherit it
Example
“Build me a landing page for my SaaS” → lead impeccable-design-polish, supports awwwards-animations and gsap-scrolltrigger, handoff video-production for hero motion.
Env vars
None required
MCP servers
Optional: magicui, chrome-devtools, playwright
Note
Four aesthetic skills — gpt-taste, industrial-brutalist-ui, minimalist-ui, high-end-visual-design — each impose a different visual language. Running two produces a blend worse than either, so exactly one per job.

Hands off to

Note
Decide, plan, build, verify, secure, perform, ship. Verification is a hard gate, not a step — most bad delivery is a skipped verification rather than a missing feature.

The eight security subagents

Dispatched in order. Findings are verified before they are patched, and redacted before they leave the machine.

cs-scan-inventory

Read-only cartographer. Partitions the repository into components and accounts for every top-level directory.

Read-only

cs-scan-researcher

Read-only. Turns one partitioned component into candidate findings with evidence.

Read-only

cs-scan-verifier

Read-only. Votes on a single candidate — the filter that removes the findings that would have been wrong.

Read-only

cs-scan-loader

Read-only. Returns one JSON file from the run directory so each job reads a fixed artifact.

Read-only

cs-scan-redactor

Read-only. Replaces credential values in finished reports with [REDACTED].

Read-only

cs-explore

Read-only. Maps where a flow is wired and every caller of a symbol, for questions the scan itself does not answer.

Read-only

cs-patch-generator

Writes. Implements one finding inside a scratch workspace and stages it as a reviewable patch file.

Writes

cs-patch-verifier

Writes. Reviews the staged diff against the finding, runs the tests, and states the claims a patch has to earn.

Writes

The honest limitation

Upstream, claude-security orchestrates its agents with Claude Code's Workflow(...) engine. That engine does not exist in opencode, so there is no one-click /security scan here. What the router ships instead is the dispatch order itself, documented above: inventory → research → verify → generate → verify patch. Running it means running those agents in sequence.

Six of the eight are read-only, which is the point — a scan that cannot write cannot damage the thing it is scanning.

Install the stack.

One line clones the repo and installs all eight routers, or name a single one.

On Windows: irm …/install.ps1 | iex — both are on the install page.
